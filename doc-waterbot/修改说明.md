# uuvmotor 每电机独立实例发布验证

本次改动目标：`uuvmotor` 从“单队列混合发布”改成“每个电机独立实例发布”。

## 1) 编译与启动

```bash
make px4_raspberrypi_default
```

启动后确认驱动在运行：

```bash
wbot_main_driver status
```

## 2) 查看多实例是否存在

在 nsh 执行（按实例号查看）：

```bash
listener uuvmotor -i 0 -n 1
listener uuvmotor -i 1 -n 1
listener uuvmotor -i 2 -n 1
listener uuvmotor -i 3 -n 1
listener uuvmotor -i 4 -n 1
listener uuvmotor -i 5 -n 1
listener uuvmotor -i 6 -n 1
listener uuvmotor -i 7 -n 1
```

预期：
- 每个实例都能读到 `uuvmotor` 消息。
- `device_id`、`motor_id` 与该实例对应的物理电机一致。

## 3) 动态验证（电机状态变化）

保持监听某个实例，然后给对应电机发送命令（例如通过 `wbot_moto_test` 或摇杆输入），观察该实例字段变化：

```bash
listener uuvmotor -i 1
```

重点看：
- `motor_speed`
- `motor_current`
- `supply_voltage`
- 故障位（如 `over_current`、`motor_fault`）

预期：
- 只有对应实例会明显变化，其他实例不应同步跟随。

## 4) 实例编号规则

当前实现使用：

```text
instance = device_id * MOTOR_MAX_INDEX + motor_id
```

其中 `MOTOR_MAX_INDEX=8`，即：
- dev0 的 motor0..7 -> instance 0..7
- dev1 的 motor0..7 -> instance 8..15

可继续验证：

```bash
listener uuvmotor -i 8 -n 1
listener uuvmotor -i 9 -n 1
```

## 5) 通过判据

满足以下条件即通过：
1. 能看到多个 `uuvmotor` 实例。
2. 每个实例有稳定独立数据。
3. 对单电机施加命令时，仅对应实例显著变化。
